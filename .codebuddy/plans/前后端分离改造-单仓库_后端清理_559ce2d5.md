## 用户需求

将已完成的前后端分离改造收尾并调整为单仓库：把前端 Vue 工程从独立仓库 `habit-agent-web` 合并进后端 `agent_demo` 仓库内的 `frontend/` 子目录，删除独立仓库，前后端统一由一个 git 仓库管理；同时补齐后端去 SSR 改造中尚未彻底收尾的残留清理工作。

## 产品概述

保持「后端纯 REST API + 前端 Vue 独立工程」的前后端分离架构不变，仅改变代码组织方式（单仓库）并彻底清理后端残留 SSR 资源。开发期前端 dev server 仍通过 Vite 代理将 `/api` 转发到后端 8080，CORS 与生产部署机制不变。

## 核心特性

- 清理后端残留的 SSR 静态资源空目录：`src/main/resources/templates/`、`src/main/resources/static/js/`（原 html/js 已删，仅空目录残留），使去 SSR 改造彻底干净
- 前端源码（Vue3+Vite+Pinia+Axios+VueRouter+ElementPlus+ECharts）整体移入 `agent_demo/frontend/`，保留「习惯记」青绿渐变视觉与 5 个页面
- 删除独立仓库 `habit-agent-web`（含其 .git），避免嵌套仓库
- `agent_demo/.gitignore` 追加 `frontend/node_modules/`、`frontend/dist/` 忽略规则
- 仓库根新增说明：后端 `mvn spring-boot:run`、前端 `cd frontend && npm install && npm run dev`
- 单一仓库统一 git 提交并推送 origin/main
- PRD 阶段三更新为「单仓库」表述并补齐子模块 3-3/3-4 验收勾选

## 技术栈选择

- 后端（已就绪，仅清理）：Spring Boot 4.1 + Java 21，仅提供 `/api` REST，CorsConfig 已允许 `http://localhost:5173`
- 前端（已就绪，仅移动）：Vue 3 + Vite 5 + Pinia 2 + Axios 1 + Vue Router 4 + Element Plus 2 + ECharts 5 + Tailwind 3.4.17

## 实现方案

### 总体策略

分两条收尾线并行合并到单仓库计划：

1. **后端清理线**：删除 `resources/templates/` 与 `resources/static/js/` 两个空目录（原 SSR 文件已删，仅目录残留），pom 已无 Thymeleaf 依赖、CorsConfig 已存在、无 PageController，本次不动任何业务代码，仅做目录级清理确保去 SSR 彻底。
2. **单仓库合并线**：将 `d:/javacode/habit-agent-web` 工程文件（排除 `node_modules/`、`dist/`、`.git`）复制到 `d:/javacode/agent_demo/frontend/`，随后删除独立仓库目录；工程内 vite 代理与 CORS 机制保持不变，联调方式不变。

### 关键技术决策

1. **清理仅删空目录、不碰业务**：核实现状——pom 已无 Thymeleaf、CorsConfig 已存在、仅 2 个 REST 控制器、GlobalExceptionHandler 已无 Thymeleaf 异常引用。残留仅为两套空目录，删除即可彻底收尾，零编译风险。
2. **复制移动而非 git submodule**：用户要求「放在一块」，采用普通子目录 `frontend/` 最直观，免去 submodule 复杂度与独立推送流程，单仓库 PR 与版本线统一。
3. **排除 node_modules/dist**：依赖与构建产物不入仓（来源仓库 .gitignore 已含），合并后由 `agent_demo/.gitignore` 统一忽略，保持仓库轻量。
4. **代理机制不变**：`frontend/vite.config.js` 的 `server.proxy['/api'] -> http://localhost:8080` 保留；同仓不影响开发联调，后端独立运行在 8080，前端 dev 在 5173。
5. **CORS 已覆盖**：后端 CorsConfig 已允许 `localhost:5173`，合并后无需改动即可联调。

### 性能与可靠性

- 后端清理为纯目录删除，`mvn compile` 不受影响（确认无文件引用这些空目录）。
- 前端移动为纯文件操作，`npm run build` 验证移动后路径无破坏（base 为相对路径，无需改）。
- 单一仓库降低多仓同步成本。

## 实现注意事项

- 复制而非 git mv（来源为另一独立仓库，历史不合并）。
- 复制后务必删除来源 `habit-agent-web` 整个目录（含 `.git`），避免 agent_demo 内出现嵌套 `.git`。
- 不修改 `agent模型.md` 及后端业务代码。
- 趋势页/AI 页仍为骨架（阶段九/五），本次不变。
