## 用户需求

修复前端「AI 分析报告」页面存在的两个问题：

1. **内容不自动生成、缺少模块级分析按钮**：进入分析报告页后，若不手动点击「生成报告」，页面仅显示空状态，不会自动产出内容；且报告页各展示模块（综合评分、今日点评、趋势总结、风险提示、改进建议、图表区、完整报告）都没有独立的「让 AI 分析」按钮，用户无法按模块触发分析。

2. **页面一直往下滑动（布局滚动 bug）**：进入分析页后整页无限向下滚动、体验极差，根因是主布局 `<main>` 未限制高度也未设为独立滚动容器，叠加 AiAdviceView 双重 `min-height` 撑高，导致 body 级无限滚动与切 tab 时滚动跳动。

## 产品概述

在现有「AI 建议」整合页（对话建议 / 分析报告两个子 tab）中的「分析报告」页，做两件事：一是让页面进入即有内容（无历史报告时自动触发一次整份 AI 分析，各模块均增加独立的「AI 分析」按钮共用生成+轮询逻辑）；二是修复整页无限滑动的布局问题，使主内容区成为固定高度、内部滚动的容器。

## 核心功能

- 进入分析报告页且本地无最新报告时，自动调用一次 `generate()` 生成整份报告，页面一进来即有内容
- 报告页各展示模块（评分环、今日点评、趋势总结、风险提示、改进建议、三个图表块、完整报告）标题区均增加「AI 分析」按钮，点击后触发整份报告重新生成（共用 `generate()`+轮询，`generating` 全局禁用所有按钮）
- 修复主布局滚动：`<main>` 改为固定高度（`calc(100vh-64px)`）+ `overflow-y-auto` 的独立滚动容器，外层 `overflow-hidden`，消除 body 级无限滚动
- 收敛 AiAdviceView 双重 `min-height`，避免与分析页卡片叠加撑高
- 后端接口与 API 封装保持不变，前端仅做视图与布局修复

## 技术栈选择

- 前端框架：Vue 3（`<script setup>` + Composition API），沿用现有项目
- UI 组件库：Element Plus（按钮 `el-button`、Loading 态、图标 `@element-plus/icons-vue`）
- 样式方案：Tailwind CSS（已有 `glass-card` 等工具类）+ 少量 scoped 样式
- 图表：vue-echarts（已有，无需改动）
- 数据流：复用 `src/api/aiAnalysis.js` 的 `generateAnalysis/getAnalysisTask/listAnalysisHistory/getLatestAnalysis`，后端 `POST /api/ai-analysis/generate` + 轮询 `/{id}`，整份异步生成

## 实现方案

### 整体策略

在**不改动后端、不改 API 封装**的前提下，仅调整前端三个文件：① `MainLayout.vue` 让主内容区成为固定高度内部滚动容器；② `AiAdviceView.vue` 收敛双重 `min-height`；③ `AiAnalysisView.vue` 增加「进页自动生成」逻辑与各模块独立「AI 分析」按钮。所有模块按钮共用已有的 `generate()` + 轮询机制，用 `generating` 状态统一禁用并显示 loading。

### 关键技术决策

1. **滚动容器收敛（治本）**：当前 `MainLayout` 外层 `min-h-screen flex flex-col`，`<main class="pt-16 flex-1">` 无高度限制，整页靠 body 自然滚动；`AiAdviceView` 的 `.ai-advice { min-height: calc(100vh - 64px) }` 再与分析页卡片 `min-h-[calc(100vh-180px)]` 叠加，长报告页必成「无限下滑」。改为：外层 `h-screen overflow-hidden`，`<main>` 设 `h-[calc(100vh-64px)] overflow-y-auto`，使滚动被限制在内容区内，window 不再无限增长。
2. **移除双重 min-height 撑高**：`AiAdviceView .ai-advice` 的 `min-height: calc(100vh - 64px)` 改为 `min-h-full`，避免与子视图高度叠加；`AiAnalysisView` 内部卡片的 `min-h-[calc(100vh-180px)]` 改为自适应（`min-h-[320px]` 即可，保证图表占位高度但不撑满视口）。
3. **进页自动生成**：在 `AiAnalysisView` 的 `init()`（onMounted + tabId watch）中，若 `loadLatest()` 返回为空，则自动调用 `generate()`；若后端因无数据返回 FAILED，捕获后在页面显示错误引导而非崩溃（`poll()` 已处理 FAILED 返回）。
4. **模块级 AI 按钮（共用生成逻辑）**：在每个模块卡片的标题行右侧加 `el-button`（小号、渐变/primary， `:loading="generating"`、`:disabled="generating"`），`@click="generate"`。所有按钮共享同一 `generating` 状态，生成中整体禁用，避免并发重复提交。整份报告一次生成即刷新全部模块，符合后端「整份生成」约束。
5. **保持视觉一致性**：按钮样式沿用 Element Plus + 现有渐变按钮 `.btn-grad`/玻璃卡，不引入新设计语言；`fade` 过渡保留但因其现在作用于固定高度滚动容器内，切 tab 不再引起 window 滚动跳动。

### 性能与可靠性

- `generate()` 走异步任务 + 轮询（每 1.5s，最多 40 次），无阻塞；轮询期间 `generating=true` 禁用全部按钮，防止重复提交。
- 进页自动生成仅在「无最新报告」时触发一次，避免每次切 tab 都重新生成（用 `task` 是否已存在判断，已有报告则不自动重生成）。
- 布局改为内部滚动容器后，图表 `autoresize` 监听的是容器 resize，不再因 window 高度突变反复触发，消除潜在重排抖动。

### 避免技术债务

- 严格复用现有 `generate/poll/loadLatest` 函数与 `aiAnalysis.js`，不重复造 HTTP 封装。
- 不改动后端 `AiAnalysisController`、实体、Service；不改动 `AiChatView`。
- 各模块按钮仅做视图层绑定，逻辑仍集中在 `AiAnalysisView`，符合现有分层与 SoC。

## 实现注意事项

- **滚动修复不要破坏其他页面**：`HomeView/TrendView/CheckinView` 等原本依赖 body 滚动，改为 `<main>` 内部滚动后，这些页面内容应正常在容器内滚动（它们本身是 `max-w-6xl mx-auto` 有限宽内容，无特殊高度依赖）；`AiChatView` 自身已是 `h-[calc(100vh-4rem)]` 内部滚动，不受影响。需本地启动验证各页面滚动正常。
- **进页自动生成的幂等**：仅在 `task.value` 为空时自动 `generate()`；`watch(tabId)` 切回 report 且已有 `task` 时不重复生成。
- **错误兜底**：`poll()` 遇到 FAILED 仅 `return`，页面保持空状态并显示「生成失败，请重试」引导（在空状态/错误分支补一个提示与重试按钮）。
- **日志**：前端无需新增日志；若需调试，沿用浏览器 console。

## 关键代码结构（接口级）

无需新增接口或类型；以下为 `AiAnalysisView.vue` 内需要调整的逻辑示意：

```js
// 现有 generate() 保持不变：提交任务 + poll() 轮询到 COMPLETED/FAILED
// init() 调整：加载最新报告，若为空则自动生成
async function init() {
  await reloadHistory()
  const res = await getLatestAnalysis()
  const t = res?.data ?? res
  if (t && t.id && t.status === 'COMPLETED') {
    task.value = t
  } else if (!t || !t.id) {
    // 无历史报告：进页即自动生成，满足「点击分析报告直接有内容」
    await generate()
  }
}
// 各模块按钮：<el-button size="small" :loading="generating" :disabled="generating" @click="generate">AI 分析</el-button>
```

## 设计风格

延续项目既有「玻璃拟态 + 流动渐变」视觉语言，不引入新设计体系。分析报告页在修复滚动与补全模块按钮后，保持清爽、分层、信息密度合理的专业仪表盘观感。

### 布局结构（分析报告页，自上而下模块）

1. **顶部操作条（玻璃卡）**：左侧标题「AI 分析报告」+ 副标题；右侧保留「刷新列表」「生成报告」主按钮，并新增整体生成态 loading。
2. **评分环 + 结构化结论区（3 列网格）**：评分环卡、今日点评卡、趋势总结卡——每个卡片标题行右侧新增小号「AI 分析」渐变按钮。
3. **风险提示卡 / 改进建议卡**：标题行右侧同样加「AI 分析」按钮。
4. **图表区（2 列网格）**：趋势分析、维度达成率、能力雷达（跨两列）三块玻璃卡，每块标题行右侧加「AI 分析」按钮；占位高度统一为 `min-h-[320px]`，避免撑满视口。
5. **完整报告卡**：标题行右侧加「AI 分析」按钮，`<pre>` 展示 Markdown 文本。
6. **历史报告条**：底部横向标签，可切换历史报告。

### 滚动修复后的视觉表现

主内容区变为固定高度（`calc(100vh-64px)`）内部滚动容器，顶部导航栏 `fixed` 始终悬浮，分析报告长内容在内容区内平滑滚动，不再出现 window 级无限下滑与切 tab 跳动，体验从「失控下滑」变为「可控内滚」。

### 交互细节

- 所有「AI 分析」按钮共用 `generating` 状态：生成中全部禁用并显示旋转 loading 图标；生成完成后恢复。
- 按钮采用 Element Plus 小号 `el-button`，主色用项目渐变 `.btn-grad` 或 `type="primary"`，与玻璃卡标题行对齐、hover 微抬升。
- `fade` 过渡保留，作用于固定高度容器内的子视图切换，不再引起全局滚动跳动。
- 无报告且自动生成失败时，空状态卡显示「生成失败，请重试」+ 重试按钮，避免白屏/崩溃。
