# 数据库表合理性检查与修复计划

## 一、检查范围

对照 PRD 需求文档、API 接口文档、详细模块开发流程，逐项检查以下数据库脚本的合理性与可用性：
- `sql/schema.sql`（MySQL 4 张表 + 种子数据）
- `sql/mongo-init.js`（MongoDB 5 个集合 + 索引 + 种子数据）
- `sql/README.md`（初始化说明文档）

## 二、检查结果总览

共发现 **6 个问题**，其中 3 个为功能性 Bug（会导致数据异常），3 个为设计缺陷（影响可用性）。

| # | 严重程度 | 问题 | 所在文件 |
|---|---|---|---|
| 1 | 功能性 Bug | user 表缺少 username UNIQUE 约束 | schema.sql |
| 2 | 功能性 Bug | habit_goal 表缺少 (user_id, goal_type) 唯一约束，种子数据 ON DUPLICATE KEY 不生效 | schema.sql |
| 3 | 功能性 Bug | reminder 种子数据 ON DUPLICATE KEY UPDATE 无唯一约束支撑，重复运行插入重复数据 | schema.sql |
| 4 | 设计缺陷 | habit_goal 表缺少 update_time 字段，API 有 PUT 更新端点 | schema.sql |
| 5 | 设计缺陷 | habit_record 种子数据 exercise_type=NULL 但 exercise_duration=0，不一致 | schema.sql |
| 6 | 设计缺陷 | MongoDB aiAnalysis 的 TTL 统一设为 1 天，WEEKLY/MONTHLY 报告不应过期 | mongo-init.js |

## 三、各问题详细分析与修复方案

### 问题 1：user 表缺少 username UNIQUE 约束

**现状**：
```sql
CREATE TABLE IF NOT EXISTS `user` (
    `id`          BIGINT       PRIMARY KEY AUTO_INCREMENT,
    `username`    VARCHAR(50)  NOT NULL COMMENT '登录用户名',
    ...
);
```

**问题**：详细模块开发流程文档明确写 `username（唯一）`，API 中 UserRepository 有 `findByUsername` 方法。但表定义无 UNIQUE 约束，无法防止重复用户名。

**修复**：在 `username` 字段上添加 UNIQUE 约束。
```sql
`username`    VARCHAR(50)  NOT NULL COMMENT '登录用户名',
...
UNIQUE KEY `uk_username` (`username`)
```

---

### 问题 2：habit_goal 表缺少 (user_id, goal_type) 唯一约束

**现状**：
```sql
CREATE TABLE IF NOT EXISTS `habit_goal` (
    ...
    INDEX `idx_user_active` (`user_id`, `is_active`),
    INDEX `idx_user_type`   (`user_id`, `goal_type`)
);
```

**问题**：
1. API 返回 40901 错误"该类型目标已存在，请使用 PUT 更新"，说明业务规则是同一用户同一类型只能有一个目标
2. 种子数据使用 `ON DUPLICATE KEY UPDATE`，但只有普通索引 `idx_user_type`，不是唯一索引，所以 ON DUPLICATE KEY 永远不会触发
3. 重复运行脚本会产生重复目标记录

**修复**：将 `idx_user_type` 改为唯一约束 `uk_user_type`。
```sql
UNIQUE KEY `uk_user_type` (`user_id`, `goal_type`) COMMENT '同用户同类型目标唯一',
```

---

### 问题 3：reminder 种子数据 ON DUPLICATE KEY 不生效

**现状**：
```sql
INSERT INTO `reminder` (...) VALUES
    (1, '睡眠打卡提醒', '23:00:00', 'SLEEP', ...),
    (1, '饮水提醒', '10:00:00', 'WATER', ...)
ON DUPLICATE KEY UPDATE `title` = VALUES(`title`);
```

**问题**：reminder 表只有主键 id 的唯一约束，没有业务唯一键。ON DUPLICATE KEY UPDATE 永远不会触发，重复运行脚本会不断插入重复提醒。

**修复**：添加 `(user_id, title)` 唯一约束（同一用户不能有同名提醒）。
```sql
UNIQUE KEY `uk_user_title` (`user_id`, `title`) COMMENT '同用户同标题提醒唯一',
```

---

### 问题 4：habit_goal 表缺少 update_time 字段

**现状**：habit_goal 表只有 `create_time`，没有 `update_time`。

**问题**：API 有 `PUT /api/goals/{id}` 更新目标端点，目标值、启用状态等都会被修改。缺少 update_time 无法追踪最后修改时间。

**修复**：添加 `update_time` 字段。
```sql
`update_time`   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
```

同时更新 HabitGoalVO 响应示例，添加 updateTime 字段。

---

### 问题 5：habit_record 种子数据 exercise 字段不一致

**现状**（第 127 行）：
```sql
(1, CURDATE() - INTERVAL 3 DAY, '01:00:00', '08:00:00', 7.00, 2, '午餐快餐，晚餐烧烤', 1, NULL,  0,  800, 2, '熬夜了'),
```

**问题**：`exercise_type = NULL`（未运动）但 `exercise_duration = 0`。两个字段不一致：如果当天没有运动，exercise_duration 也应该为 NULL。值为 0 会影响统计平均值（API 返回 `avgExerciseDuration` 时会被拉低）。

**修复**：将 `exercise_duration` 从 `0` 改为 `NULL`。
```sql
(1, CURDATE() - INTERVAL 3 DAY, '01:00:00', '08:00:00', 7.00, 2, '午餐快餐，晚餐烧烤', 1, NULL,  NULL, 800, 2, '熬夜了'),
```

### 问题 6：MongoDB aiAnalysis TTL 统一 1 天，WEEKLY/MONTHLY 报告不应过期

**现状**：
```javascript
// TTL 索引 — 缓存 1 天自动过期
db.aiAnalysis.createIndex(
    { "expireAt": 1 },
    { name: "ttl_expire_at", expireAfterSeconds: 0, background: true }
);
```

种子数据中 WEEKLY 和 DAILY 都设 `expireAt: new Date(Date.now() + 24 * 3600000)`（1 天后过期）。

**问题**：API 有 `GET /api/ai-analysis?type=WEEKLY` 列出历史分析结果。如果 WEEKLY/MONTHLY 报告 1 天后就过期删除，用户永远看不到历史报告。只有 DAILY 评价需要 1 天缓存（避免当天重复调用 AI），WEEKLY/MONTHLY 报告应长期保留。

**修复**：
1. TTL 索引保持不变（仍用 expireAt 字段控制过期）
2. 修改种子数据和文档说明：
   - DAILY 类型：`expireAt = createTime + 1 天`（1 天缓存）
   - WEEKLY 类型：`expireAt = null`（永不过期）
   - MONTHLY 类型：`expireAt = null`（永不过期）
   - CUSTOM 类型：`expireAt = null`（永不过期）
3. 在 TTL 索引说明中添加 `sparse: true`，使 expireAt 为 null 的文档不被 TTL 删除

```javascript
db.aiAnalysis.createIndex(
    { "expireAt": 1 },
    { name: "ttl_expire_at", expireAfterSeconds: 0, background: true, sparse: true }
);
```
