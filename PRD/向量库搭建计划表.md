# 生活习惯助手 Agent — 向量库下载安装使用搭建计划表

> 面向后端开发和 AI Agent 小白，从零开始搭建 MongoDB Atlas Vector Search 向量库。
> 本文档涵盖账号注册、集群创建、索引配置、Spring AI 集成、验证测试的全流程。
> 技术栈：MongoDB Atlas Vector Search + Spring AI 2.0 + DashScope text-embedding-v3

---

## 一、背景知识

### 1.1 什么是向量库

向量库是一种专门存储和检索"向量"（高维浮点数数组）的数据库。在 AI 应用中，大语言模型无法直接理解中文文本的语义关系，需要先将文本转换为向量（一串数字），再通过计算向量之间的距离来判断两段文本的语义相似度。

打个比方：你在图书馆找"如何改善睡眠"的书，传统数据库只能按书名精确匹配搜索；向量库则能理解"改善睡眠"和"提高睡眠质量"表达的是相近的意思，把语义相近的内容都找出来。

### 1.2 向量库在本项目中的作用

本项目是一个"生活习惯助手 Agent"，其中 RAG（检索增强生成）模块需要向量库支撑。工作流程如下：

```
用户提问："我最近睡眠不好怎么办？"
    ↓
1. DashScope Embedding 模型将问题转为 1024 维向量
    ↓
2. MongoDB Atlas Vector Search 在 habit_knowledge 集合中搜索语义最相近的知识文档
    ↓
3. 检索到："成人每天建议睡眠7-9小时，最佳入睡时间为22:00-23:00..."
    ↓
4. 将检索到的知识文档 + 用户问题一起发送给通义千问大模型
    ↓
5. 大模型结合知识库内容生成专业回答
    ↓
6. 后端（RagController / ChatController）将回答封装为 `Result` JSON，经 `/api` 返回给前端
    ↓
7. 前端 Vue 工程（agent_demo/frontend/）在 AI 建议页渲染回答
```

> **架构说明**：向量库完全属于后端服务范畴。单仓库前端工程 `agent_demo/frontend/`（Vue 3 + Vite）不直接访问 MongoDB Atlas，而是通过调用后端 REST API（如 `/api/chat`、`/api/rag/*`）间接使用向量检索能力。本文档只描述后端向量服务的搭建。

如果没有向量库，大模型只能根据自己的训练数据回答问题，无法结合项目预置的健康知识库；有了向量库，Agent 的回答就有了可靠的、可更新的知识来源。

### 1.3 为什么选 MongoDB Atlas Vector Search

本项目已经使用 MongoDB 存储对话记忆、AI 分析结果等文档型数据。MongoDB Atlas Vector Search 是 MongoDB 官方提供的向量检索能力，无需引入额外的向量数据库（如 Milvus、Pinecone），一套 MongoDB 同时承担文档存储和向量检索两个角色，降低了运维复杂度。

Spring AI 2.0 对 MongoDB Atlas Vector Store 提供了原生自动配置支持（`spring-ai-starter-vector-store-mongodb-atlas`），项目中 `pom.xml` 已引入该依赖。

### 1.4 本地 MongoDB 与 MongoDB Atlas 的关系

这是一个新手最容易混淆的点，需要特别说明：

| 对比项 | 本地 MongoDB（Community Edition） | MongoDB Atlas（云服务） |
|---|---|---|
| 安装方式 | 本机安装或 Docker 运行 | 云端托管，无需安装 |
| 向量搜索 | 不支持 `$vectorSearch` | 支持 Atlas Vector Search |
| 费用 | 免费 | 免费层 M0（512MB）足够学习使用 |
| 适用场景 | 日常 CRUD 开发调试 | 向量检索 + 生产部署 |

**结论**：由于向量搜索（`$vectorSearch`）是 MongoDB Atlas 的专有功能，本地社区版 MongoDB 不支持，本项目需要使用 MongoDB Atlas 云数据库。建议将所有 MongoDB 数据（对话记忆、AI 分析、向量存储）统一放到 Atlas 上，避免维护两套数据库连接。

## 三、MongoDB Atlas 注册与集群创建

### 3.1 注册 MongoDB Atlas 账号

1. 打开浏览器，访问 https://www.mongodb.com/cloud/atlas/register
2. 填写邮箱、密码、姓名，或直接使用 Google 账号登录
3. 在"Tell us a bit about yourself"页面：
   - Role：选择 `Developer` 或 `Student`
   - Project：选择 `Just Learning` 或 `Personal Project`
   - Primary language：选择 `Java`
4. 点击 `Finish` 完成注册

### 3.2 创建免费集群（M0）

注册成功后会自动进入集群创建向导：

1. **选择部署方案**：点击 `Create` 按钮，选择 `M0 Free`（免费层）
2. **选择云服务商**：推荐选择 `AWS`（亚太节点较多，延迟较低）
3. **选择区域**：推荐选择 `Singapore`（新加坡），国内访问延迟相对较低
   - 如果你在中国大陆且网络条件允许，也可以选择 `Google Cloud` 的 `Taiwan` 区域
4. **集群配置**：
   - Cluster Tier：`M0 Free`（512MB 存储，512MB 内存）
   - Cluster Name：保持默认 `Cluster0`，或改为 `habit-agent-cluster`
5. 点击 `Create Cluster`，等待集群创建完成（通常需要 3-5 分钟）

### 3.3 集群创建完成后的界面

集群创建完成后，你会看到 Atlas 控制台首页。此时需要进行三项配置才能使用：

- **Database Access**：创建数据库用户（设置用户名和密码）
- **Network Access**：配置 IP 白名单（允许你的电脑连接）
- **Database**：获取连接字符串

下面分步骤说明。

## 四、数据库访问配置

### 4.1 创建数据库用户

1. 在 Atlas 控制台左侧菜单，点击 `Database Access`（或点击首页的 `Add Database User` 按钮）
2. 点击右侧 `+ Add New Database User` 按钮
3. 填写用户信息：
   - Authentication Method：选择 `Password`
   - Username：输入 `habitadmin`（自定义，记住这个用户名）
   - Password：点击 `Autogenerate` 自动生成密码，或手动输入一个强密码
   - **重要**：将用户名和密码记录下来，后面配置 `application.yml` 时需要用到
4. Database User Privileges：选择 `Read and write to any database`（学习和开发阶段使用，生产环境应限制权限）
5. 点击 `Add User` 完成创建

### 4.2 配置网络访问（IP 白名单）

MongoDB Atlas 默认拒绝所有外部连接，需要将你的电脑 IP 加入白名单：

1. 在 Atlas 控制台左侧菜单，点击 `Network Access`
2. 点击 `+ Add IP Address` 按钮
3. 选择以下方式之一：
   - 点击 `ADD CURRENT IP ADDRESS`：自动添加你当前电脑的公网 IP
   - 如果你的 IP 是动态的（大多数家庭宽带），建议在 `Access List Entry` 中输入 `0.0.0.0/0`（允许所有 IP 连接）
     - 注意：`0.0.0.0/0` 仅建议在开发学习阶段使用，生产环境应限制为具体 IP
4. Comment：填写备注，如 `开发电脑`
5. 点击 `Confirm` 完成添加

> 如果使用 `0.0.0.0/0`，Atlas 可能会提示安全警告，确认即可。学习项目无需担心。

### 4.3 获取连接字符串

1. 在 Atlas 控制台首页，点击集群下方的 `Connect` 按钮
2. 在弹出的连接方式选择中，点击 `Drivers`
3. 在驱动列表中选择 `Java`（或保持默认）
4. 找到 `Connection String`，复制完整的连接字符串，格式如下：

```
mongodb+srv://habitadmin:<db_password>@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority&appName=Cluster0
```

5. **重要操作**：将 `<db_password>` 替换为你在步骤 4.1 中设置的密码
6. 将替换后的完整连接字符串记录下来，后面配置 `application.yml` 时需要用到

> 连接字符串中的 `xxxxx` 是 Atlas 自动生成的集群标识符，每个账户不同，不要修改。

## 五、DashScope API 密钥申请

向量库需要 Embedding 模型将文本转为向量。本项目使用阿里云百炼平台的 `text-embedding-v3` 模型。

### 5.1 注册阿里云账号并开通百炼服务

1. 访问 https://bailian.console.aliyun.com/
2. 使用阿里云账号登录（如果没有，先注册阿里云账号）
3. 首次进入会提示开通百炼服务，点击同意开通（免费开通，按调用量计费，新用户有免费额度）

### 5.2 获取 API Key

1. 在百炼控制台页面，将鼠标移到右上角头像，点击 `API-KEY`
2. 在弹出的 API Key 管理页面，点击 `创建新的 API-KEY`
3. 业务空间选择默认空间，描述填写 `habit-agent`（便于识别）
4. 点击确定，复制生成的 API Key
   - 格式示例：`sk-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`
   - **重要**：API Key 只在创建时显示一次，请立即复制保存
5. 确认已开通 Embedding 模型权限：
   - 在百炼控制台左侧菜单点击 `模型广场`
   - 搜索 `text-embedding-v3`
   - 确认该模型状态为 `已开通` 或点击 `开通服务`（通常免费额度内无需额外操作）

### 5.3 配置环境变量

将 API Key 配置为系统环境变量，避免硬编码到代码中：

**Windows 系统（PowerShell）**：

```powershell
# 永久设置环境变量（推荐）
[System.Environment]::SetEnvironmentVariable("DASHSCOPE_API_KEY", "你的API Key", "User")

# 验证是否设置成功
echo $env:DASHSCOPE_API_KEY
```

设置完成后，**需要重启 IDE（IntelliJ IDEA / VS Code）** 让环境变量生效。

**验证环境变量是否生效**：

在 IDE 的终端中执行：
```powershell
echo $env:DASHSCOPE_API_KEY
```
如果输出了你的 API Key，说明配置成功。

## 六、MongoDB Atlas Vector Search 索引创建

向量检索依赖一个特殊的"向量搜索索引"。必须在 Atlas 控制台手动创建，Spring AI 无法自动创建此索引。

### 6.1 创建数据库和集合

1. 在 Atlas 控制台首页，点击集群下方的 `Browse Collections`（或 `Collections`）
2. 点击 `Add My Own Data`（或 `Create Database`）
3. 填写信息：
   - Database Name：`habit_agent`
   - Collection Name：`habit_knowledge`
4. 点击 `Create` 完成创建

此时 `habit_knowledge` 集合是空的，没关系，后续 Spring AI 会自动向其中写入向量化后的文档。

### 6.2 创建 Vector Search 索引

这是最关键的一步：

1. 在 Atlas 控制台左侧菜单，点击 `Atlas Search`（或 `Search`）
2. 确保选择了正确的集群（如 `Cluster0`）和数据库（`habit_agent`）
3. 点击 `Create Search Index`
4. 在索引创建页面：
   - Index Type：选择 `Atlas Vector Search`
   - Index Name：输入 `habit_vector_index`
   - Database：选择 `habit_agent`
   - Collection：选择 `habit_knowledge`
5. 在 JSON 定义编辑器中，粘贴以下配置：

```json
{
  "fields": [
    {
      "type": "vector",
      "path": "embedding",
      "numDimensions": 1024,
      "similarity": "cosine"
    },
    {
      "type": "filter",
      "path": "metadata.doc_type"
    },
    {
      "type": "filter",
      "path": "metadata.source"
    }
  ]
}
```

**配置说明**：

| 字段 | 值 | 说明 |
|---|---|---|
| type: vector | 向量字段 | 告诉 Atlas 这是一个向量类型索引 |
| path | `embedding` | 向量数据存储在文档的 `embedding` 字段中（Spring AI 默认字段名） |
| numDimensions | `1024` | DashScope text-embedding-v3 默认输出 1024 维向量 |
| similarity | `cosine` | 余弦相似度，适合文本语义搜索 |
| type: filter | 过滤字段 | 允许按 `metadata.doc_type` 和 `metadata.source` 过滤检索结果 |

6. 点击 `Create Search Index`
7. 等待索引状态从 `Building` 变为 `Active`（通常需要 1-3 分钟）

> 如果索引状态长时间停留在 `Building`，检查集合中是否已有数据。空集合的索引可能需要手动添加一条文档后才会激活。

### 6.3 验证索引状态

1. 在 `Atlas Search` 页面，确认 `habit_vector_index` 的状态为 `Active`
2. 确认关联的集合为 `habit_agent.habit_knowledge`

## 七、Spring AI 项目配置

### 7.1 application.yml 完整配置

将 `src/main/resources/application.yml` 更新为以下内容（替换占位符为你的实际值）：

```yaml
server:
  port: 8080

spring:
  application:
    name: habit-agent

  # ============================
  # MySQL 数据源（业务数据）
  # ============================
  datasource:
    url: jdbc:mysql://localhost:3306/habit_agent?useUnicode=true&characterEncoding=utf-8&useSSL=false&serverTimezone=Asia/Shanghai
    username: root
    password: 你的MySQL密码
    driver-class-name: com.mysql.cj.jdbc.Driver

  jpa:
    hibernate:
      ddl-auto: update
    show-sql: true
    properties:
      hibernate:
        format_sql: true
        dialect: org.hibernate.dialect.MySQLDialect

  # ============================
  # MongoDB Atlas（文档数据 + 向量存储共用连接）
  # 将 <db_password> 替换为步骤 4.1 中设置的密码
  # 将 xxxxx 替换为你的集群标识符
  # ============================
  data:
    mongodb:
      uri: mongodb+srv://habitadmin:<db_password>@cluster0.xxxxx.mongodb.net/habit_agent?retryWrites=true&w=majority&appName=Cluster0
      auto-index-creation: true

  # ============================
  # Spring AI 配置
  # 通过 OpenAI 兼容模式接入 DashScope（通义千问 + Embedding）
  # ============================
  ai:
    openai:
      base-url: https://dashscope.aliyuncs.com/compatible-mode
      api-key: ${DASHSCOPE_API_KEY}
      chat:
        options:
          model: qwen-plus
          temperature: 0.7
      embedding:
        options:
          model: text-embedding-v3
    # ============================
    # MongoDB Atlas 向量存储配置
    # ============================
    vectorstore:
      mongodb:
        initialize-schema: false
        collection-name: habit_knowledge
        vector-index-name: habit_vector_index
        path-name: embedding
        metadata-fields-to-filter: doc_type,source
```

**关键配置项说明**：

| 配置项 | 值 | 说明 |
|---|---|---|
| `spring.data.mongodb.uri` | Atlas 连接字符串 | 指向 MongoDB Atlas 云集群，不是 localhost |
| `spring.ai.openai.base-url` | DashScope 兼容端点 | 让 Spring AI 把请求转发到阿里云 DashScope |
| `spring.ai.openai.api-key` | `${DASHSCOPE_API_KEY}` | 从环境变量读取，不硬编码 |
| `spring.ai.openai.embedding.options.model` | `text-embedding-v3` | 阿里云文本向量化模型 |
| `vectorstore.mongodb.initialize-schema` | `false` | 索引已在步骤 6.2 手动创建，设为 false 避免冲突 |
| `vectorstore.mongodb.collection-name` | `habit_knowledge` | 与步骤 6.1 创建的集合名一致 |
| `vectorstore.mongodb.vector-index-name` | `habit_vector_index` | 与步骤 6.2 创建的索引名一致 |
| `vectorstore.mongodb.path-name` | `embedding` | 向量字段路径，与索引 JSON 中 path 一致 |

### 7.2 关于 initialize-schema 的说明

Spring AI 提供 `initialize-schema: true` 自动创建向量索引的功能。但由于以下原因，建议手动创建并设为 `false`：

- 自动创建的索引是基础版本，不支持 filter 字段（我们需要按 `doc_type` 和 `source` 过滤）
- 自动创建在某些 Atlas 版本上可能失败
- 手动创建可以更精确地控制索引参数

如果你不想手动创建索引，可以将 `initialize-schema` 设为 `true`，但需要将索引 JSON 中的 filter 字段移除，并接受简化版的索引。

### 7.3 MongoDB 连接字符串安全建议

生产环境中，数据库密码不应直接写在 `application.yml` 中。推荐以下做法：

**方案一：环境变量（开发阶段推荐）**

```yaml
spring:
  data:
    mongodb:
      uri: ${MONGODB_URI:mongodb+srv://habitadmin:password@cluster0.xxxxx.mongodb.net/habit_agent}
```

然后在环境变量中设置 `MONGODB_URI`。

**方案二：Spring profiles 分环境配置**

创建 `application-dev.yml`（开发环境，密码明文）和 `application-prod.yml`（生产环境，从环境变量读取），通过 `spring.profiles.active` 切换。

## 八、功能验证与测试

### 8.1 项目启动验证

完成上述配置后，启动 Spring Boot 项目：

1. 在 IDE 中运行 `HabitAgentApplication.java`
2. 观察控制台日志，确认以下信息：
   - 无报错信息
   - 日志中出现 MongoDB 连接成功的标志（如 `Cluster description` 或 `Connected to cluster`）
   - 日志中出现 Spring AI 相关的 Bean 初始化（如 `OpenAiEmbeddingModel`、`MongoDBAtlasVectorStore`）

**常见启动报错**：

| 报错信息 | 原因 | 解决方案 |
|---|---|---|
| `connection timed out` | IP 未加入白名单 | 回到步骤 4.2 添加 IP 或设置 `0.0.0.0/0` |
| `Authentication failed` | 用户名或密码错误 | 检查连接字符串中的用户名密码是否与步骤 4.1 一致 |
| `DASHSCOPE_API_KEY is null` | 环境变量未生效 | 重启 IDE，或检查环境变量设置 |
| `vector index not found` | 索引未创建或名称不匹配 | 回到步骤 6.2 确认索引名称为 `habit_vector_index` |

### 8.2 向量写入测试

项目启动成功后，可以通过以下方式测试向量写入功能。在项目开发到阶段七（RAG 模块）时，会有完整的 RagService 实现文档导入功能。在此之前的验证方法：

**方法一：编写临时测试类**

在 `src/test/java/com/habit/agent/` 下创建 `VectorStoreTest.java`：

```java
package com.habit.agent;

import org.junit.jupiter.api.Test;
import org.springframework.ai.document.Document;
import org.springframework.ai.vectorstore.VectorStore;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.context.SpringBootTest;

import java.util.List;
import java.util.Map;

@SpringBootTest
class VectorStoreTest {

    @Autowired
    private VectorStore vectorStore;

    @Test
    void testAddAndSearch() {
        // 1. 写入测试文档（Spring AI 自动调用 DashScope 生成向量并存储到 MongoDB）
        Document doc1 = new Document(
            "成人每天建议睡眠7-9小时，最佳入睡时间为22:00-23:00。",
            Map.of("doc_type", "sleep_guide", "source", "test")
        );
        Document doc2 = new Document(
            "每周推荐中等强度运动150分钟或高强度运动75分钟。",
            Map.of("doc_type", "exercise_guide", "source", "test")

        // 2. 验证写入成功：在 Atlas 控制台 Browse Collections 中查看 habit_knowledge 集合
        //    应能看到两条文档，每条包含 content、metadata、embedding 字段
```

## 八-B、RAG 接入时序与本地降级方案

> 本章细化向量库在 RAG（检索增强生成）链路中的接入时序，以及当 Atlas / DashScope 不可用时如何降级，保证对话与建议功能不中断。对应开发计划「阶段七 RAG 知识库」「阶段九 多智能体路由」与《API接口设计方案.md》RagController / ChatController 设计。

### 8-B.1 RAG 检索增强接入时序

RAG 由 `RetrievalAugmentationAdvisor` 注入到 ChatClient 调用链。完整时序如下（以用户提问"我最近睡眠不好怎么办"为例）：

```
┌────────┐    ┌────────────┐    ┌──────────────┐    ┌──────────────┐    ┌────────────┐    ┌──────────┐
│ 前端   │    │后端        │    │VectorStore   │    │DashScope     │    │通义千问   │    │Atlas     │
│(Vue)   │    │(Controller)│    │(Atlas)       │    │Embedding     │    │(qwen-plus)│    │(Mongo)   │
└───┬────┘    └─────┬──────┘    └──────┬───────┘    └──────┬───────┘    └────┬─────┘    └────┬─────┘
    │  GET /api/chat/stream?message=…  │                   │                  │              │
    │─────────────────────────────────>│                   │                  │              │
    │                                   │ ① 问题向量化      │                  │              │
    │                                   │（Advisor 内部触发）│                  │              │
    │                                   │──────────────────>│ ② embed(text)    │              │
    │                                   │<──────────────────│ 1024维向量        │              │
    │                                   │                   │                  │              │
    │                                   │ ③ $vectorSearch   │                  │              │
    │                                   │    topK=3         │                  │              │
    │                                   │───────────────────────────────────────────────────>│
    │                                   │<──────────────────────────── Top-K 文档片段 ───────│
    │                                   │                   │                  │              │
    │                                   │ ④ 组装 Prompt:     │                  │              │
    │                                   │  [知识片段]+[问题] │                  │              │
    │                                   │──────────────────────────────────>│ ⑤ 生成回答    │
    │           ⑥ SSE event: chunk      │<──────────────────────────────────│              │
    │<══════════════════════════════════│                   │                  │              │
    │           ⑦ SSE event: done       │                   │                  │              │
    │<══════════════════════════════════│                   │                  │              │
```

**时序关键点说明**：

| 步骤 | 触发方 | 动作 | 失败处理 |
|---|---|---|---|
| ① 问题向量化 | RetrievalAugmentationAdvisor | 调用 DashScope `text-embedding-v3` | 见 8-B.3 降级 |
| ③ 向量检索 | MongoDBAtlasVectorStore | `$vectorSearch` topK=3，cosine | 见 8-B.3 降级 |
| ④ Prompt 组装 | Advisor | 将检索片段注入 `userText` | 检索为空时跳过注入 |
| ⑤ 生成 | 通义千问 qwen-plus | 流式返回 | SSE `error` 事件 |

### 8-B.2 RAG 知识库写入时序（RagController `/api/rag/import`）

```
POST /api/rag/import
  → RagService.importPresetDocs()
      → 读取 rag-docs/*.md（sleep-guide / exercise-guide / diet-guide）
      → TextReader 解析为 Document 列表
      → TokenTextSplitter 分块（默认 chunkSize=500, overlap=100）
      → vectorStore.add(docs)  // 内部逐条调用 DashScope Embedding 向量化并写入 Atlas
      → 返回 ImportResultVO{ totalDocs, totalChunks, success, errors }
```

> 分块策略：知识库文档较短（每篇约 300-600 字），`TokenTextSplitter` 按 token 切分，避免单块超 Embedding 模型上下文；`metadata.doc_type` / `metadata.source` 携带以便 Atlas 索引 filter 与前端分类展示。

### 8-B.3 本地降级方案（已落地）

当 Atlas 向量库或 DashScope Embedding 不可用时，需保证对话 / 建议主链路不中断。降级策略分两级：

**一级降级：检索降级（无知识库增强）**
- 触发条件：`vectorStore.similaritySearch` 抛异常或返回空，或 Embedding 调用超时（`50302 AI_TIMEOUT`）。
- 行为：`SafeRetrievalAdvisor` 捕获异常后**跳过知识注入**，直接以原始问题调用通义千问；`/api/chat/stream` 正常输出 SSE chunk，不触发 error 事件。
- 实现（已落地）：新增 `com.habit.agent.agent.advisor.SafeRetrievalAdvisor`（order=HIGHEST+150，2026-08-05 由 +300 前移以避免与 `ToolCallingAdvisor`(+300) 的 order 冲突），内部委托官方 `RetrievalAugmentationAdvisor`，对 `adviseCall` / `adviseStream` 均 try-catch，异常时 `chain.nextCall(request)` / `chain.nextStream(request)` 放行原始请求并打 WARN 日志；流式链路额外加 `onErrorResume` 覆盖响应式流异步异常（仅兜底检索阶段，不再包裹工具循环）。
- 用户感知：回答仍可用，但缺少项目知识库依据（如通用睡眠建议而非基于 `sleep-guide.md`）。

**二级降级：对话降级（本地兜底）**
- 触发条件：DashScope 完全不可用（`50301 AI_SERVICE_UNAVAILABLE` / `50303 AI_SAFETY_BLOCKED`）。
- 行为：后端返回缓存的通用健康建议模板或 SSE `error` 事件，前端 `AiChatView` 展示"AI 服务暂时不可用，请稍后再试"，不阻塞打卡/历史/目标等已落地功能。
- 实现建议：`GlobalExceptionHandler` 统一映射 `50002/50301` → 友好提示；已落地的 Habit/Goal/Analysis 三大模块不依赖 AI，照常服务。

**本地离线向量方案（无 Atlas 时开发调试）**
- 使用 Spring AI `SimpleVectorStore`（内存级，启动时从 `rag-docs/` 加载并 Embedding，重启丢失）做本地调试，避免强依赖 Atlas。
- 切换方式：通过 `spring.profiles.active=local` 启用 `application-local.yml`，将 `vectorstore` 实现替换为 `SimpleVectorStore`，Embedding 仍可用 DashScope（或本地 `OllamaEmbeddingModel` 完全离线）。
- 注意：本地降级仅用于开发调试，生产必须回到 MongoDB Atlas Vector Search 以保证向量持久化与多实例共享。

## 十一、常见问题与排障指南

### Q1：Atlas 连接超时，提示 connection timed out

**原因**：你的电脑 IP 不在 Atlas 白名单中。

**解决**：
1. 登录 Atlas 控制台 → `Network Access`
2. 检查是否有你当前 IP 的条目
3. 如果没有，点击 `Add IP Address` → `ADD CURRENT IP ADDRESS`
4. 如果你的 IP 经常变化，添加 `0.0.0.0/0`（允许所有 IP）
5. 等待 1-2 分钟让配置生效后重试

### Q2：启动报错 "vector index not found" 或 "SearchIndex not found"

**原因**：向量搜索索引未创建，或名称不匹配。

**解决**：
1. 登录 Atlas 控制台 → `Atlas Search`
2. 确认索引名称为 `habit_vector_index`（与 application.yml 中 `vector-index-name` 一致）
3. 确认索引关联的集合为 `habit_agent.habit_knowledge`
4. 确认索引状态为 `Active`（不是 `Building`）
5. 如果索引不存在，回到步骤 6.2 重新创建

### Q3：Embedding 调用报错 "Invalid API Key" 或 401 Unauthorized

**原因**：DashScope API Key 未配置或配置错误。

**解决**：
1. 在终端执行 `echo $env:DASHSCOPE_API_KEY`，确认输出不为空
2. 如果为空，重新设置环境变量并重启 IDE
3. 登录百炼控制台确认 API Key 未被禁用或删除
4. 确认 `application.yml` 中 `api-key` 的值为 `${DASHSCOPE_API_KEY}`（注意花括号和美元符号）

### Q4：向量维度不匹配，报错 "dimension mismatch"

**原因**：索引定义中的 `numDimensions` 与 Embedding 模型实际输出的维度不一致。

**解决**：
1. DashScope `text-embedding-v3` 默认输出 1024 维
2. 确认 Atlas 索引 JSON 中 `numDimensions` 为 `1024`
3. 如果使用了其他 Embedding 模型（如 OpenAI text-embedding-3-small 输出 1536 维），需要同步修改索引维度

### Q5：Atlas 免费层 M0 够用吗？有什么限制？

M0 免费层的限制：
- 存储：512MB（对学习项目完全够用）
- 内存：512MB
- 不支持集群扩容（如需更多资源需升级到 M10+）
- Vector Search 查询次数：无硬性限制，但并发能力有限

对于本项目（3 篇知识库文档，约 20 个文本块），512MB 绰绰有余。

### Q6：能否不使用云数据库，用本地 MongoDB 实现向量搜索？

本地 MongoDB Community Edition 不支持 `$vectorSearch` 聚合操作符，因此无法使用 MongoDB Atlas Vector Search 功能。

如果确实需要完全离线开发，可以考虑以下替代方案（但需要修改项目代码和依赖）：
- 使用 Spring AI 的 `SimpleVectorStore`（内存级向量存储，重启后丢失数据，仅用于测试）
- 使用 Chroma（本地轻量向量数据库，Docker 部署）
- 使用 Milvus（功能更强的向量数据库，但部署复杂度高）

本项目选择 MongoDB Atlas 是因为它与已有的 MongoDB 数据层共用一套连接，配置最简单。

### Q7：MongoDB Atlas 在国内访问慢怎么办？

- 选择 `Singapore` 或 `Taiwan` 区域的集群，延迟通常在 100-300ms
- 如果使用 `0.0.0.0/0` 白名单，Atlas 的全球 CDN 会自动路由到最近的节点
- 向量检索的延迟主要来自 Embedding API 调用（DashScope 在国内有节点），MongoDB 查询本身通常在 50ms 以内
- 如果延迟严重影响开发体验，可以考虑使用代理或 VPN
